# 随蓝射覆 · 在线 2v2（实验版）

> 给 AI Agent 的交接手册见 [`AGENTS.md`](./AGENTS.md)：架构、规则不变量、测试、发布、踩坑都在那里。
> 面向玩家的规则说明继续往下读本文件。

独立于主持人工作台的实验分支。原版工作台（`随蓝射覆1`）不做任何改动。

**进来就能看到棋盘**：把房间链接发出去，任何人点开即是这局的一份全屏视图 ——
棋盘、席位、对局历史都在同一页。想下场就点一个空席位，不想下场就是观众；
观众同样能设昵称，也能上传题库给房主审批。

落地页有**房间大厅**：列出所有还开着的房间（阶段、入座数、观战人数、题库），
点一行就能进，不用先向别人要房号；大厅 5 秒自动刷新，已解散的房间会立刻消失。

大厅还会**顺手清掉废弃房**：建完房没等来人就关掉页面，20 分钟后会自动消失（对局中 1 小时、
已结束 2 小时），房号随即回收。判的是「最后一次有人在线」而不是「最后一次操作」——
页面开着就一直算在线，所以真在等人的房不会被误清。

房间只存在服务端进程的内存里，**不依赖任何云服务**：对局期间一切正常，重新发布或进程重启后房间清空。
按目前的取舍，打完的对局**不留存档**（原先的「我的战绩」已下线），想要长期记录需要另接一个存储。

对局由服务端进程裁决，关掉任何一台设备（包括房主）都不影响其他三家继续打。

## 规则实现（按需求落地）

1. **四席**：红队 / 绿队各有「描述位」和「猜词位」，无需主持人。
2. **题库**：房间里**任何人都能上传**（选手、观众、房主），传完进待审批列表，
   **房主同意后**才成为本局题库。房间没有题库时棋盘上写着「等待导入本局题库」。
   两条导入路线——
   - **明文词库**：粘贴或读入文本，**换行 / 逗号 / 顿号 / 分号 / 空格 / Tab 都算分隔**，
     序号（`1.`、`②`、`三、`）、项目符号、引号书名号都会自动剥掉；识别结果**实时显示在下面，
     可以逐条改、删、补**，改完再提交。也支持每行 `词|提示|分类`（与打包脚本的 `.txt` 同格式）。
     斜杠 `甲/乙` 表示**同一个词的两种写法**：算一个词，猜中任一种都判对，
     棋盘、结算与对局历史里只显示斜杠前那个。
   - **加密包**：`.sbank` + 口令，词表在服务端解密。
   无论哪条路线，词表都只留在服务端 `vault`，任何设备的快照里都拿不到未揭晓的答案。
3. **开局**：四席坐满 + 题库就绪 + **四位选手都点「准备」** → 自动开局。
   不需要房主再点一次开始；房主可以一直待在观战席，只负责审批题库。
4. **回合**：选格方描述位先选格 → 双方描述位同时收到答案 → 选格方描述、本方猜词位作答；
   答对即占领并获得下一格选格权；**答错不换格**，改由对方描述、对方作答，
   两队就这么交替下去（红描-红答-绿描-绿答-红描……），**直到有人猜对为止**。
5. **描述固定两个字**：正好两个汉字，且不能出现答案里的任何一个字。
   输入过程中不打扰，**只在点提交后**才提示哪里不合规；服务端用同一份判定再验一次。
6. **两段独立行动**：描述位提交描述 → 猜词位作答，各自有独立的 90 秒。
   **描述超时不算回合结束**：描述作废，仍由本方猜词位直接作答（凭格子代号与字数猜）；
   作答再超时，才交棒给对方描述。任何选手也可以随时主动「跳过」自己此刻的行动，
   规则与超时完全一致（选格跳过 = 选格权给对方）。
7. **对局历史**：**整局**每个格子一行，按发生顺序铺开
   「红方描述 → 红方猜词 → 绿方描述 → 绿方猜词 → 答案 ✓」。
   超时和主动跳过也按**本阵营的颜色**记录（红字/绿字），不吞成灰字；答对收尾。
   不只当前格，已完成的格子会一直留在表里。
8. **抢答**：对方描述之后、作答之前，本方猜词位可抢答，答题时间缩到 20 秒；答对拿格，
   答错仍由对方继续作答。预算：红方每行一次、绿方每列一次（没抢到不消耗）。
   **防抢答**是「在自己的作答窗口抢答本应自己答的题」：等你这边进入作答（描述已提交）后，
   本方猜词位可以把答题权先锁住，对方就抢不了了，同样按 20 秒作答；
   **它不消耗抢答次数**（抢的是自己的题）。抢答功能开局前可选，默认关闭。
9. **暂停**：任意选手可随时按「暂停」，计时与所有行动冻结；任意选手（或房主）点「继续」后，
   暂停时长整体顺延，不吃时间。
10. **复制局面图**：随时可以把局面生成成一张 PNG 并**直接复制到剪贴板**（棋盘 + 四位选手昵称 +
    全部对局历史），粘到会话窗口即可分享；剪贴板不可用时才退化成下载文件。
11. **解散房间**：房主（或开发者）可在顶栏「解散房间」结束本局——第一次点击只进入确认态，
    4 秒内再次点击才生效。解散后所有人看到「房间已解散」，房号立即释放，可被新房重用。
12. **重开**：对局中或结束后，顶栏的「重开」按钮按席位发起——**四个席位各点一次同意**
    （按钮上直接显示 n/4 票，再点一次即撤销同意），四票齐了立刻开新局：
    棋盘、对局历史、回合与抢答预算清零，人员、题库与抢答设定沿用；
    优先发题库里**还没上过场**的词，不够 25 个才整份重洗。
13. **观众猜词**：坐在场边的人也能在对局过程中猜「现在这一格的词是什么」。
    猜中**不会替任何一方拿格**，只在战况里写一句「观众 xx 猜中了 A2 格」——
    **猜的是什么词一个字都不会写出来**；猜错只回给猜的人自己一句「未命中」，不进战况。
    同一个人对同一格最多猜 10 次，换格即清零。

## 开发者模式（原来的机器人机制）

机器人已从玩法里移除，改成纯测试工具：

- **不会自己行动**。服务端不再有任何自动决策循环，四席永远等真人的操作。
- **隐藏开启方式**：在落地页依次敲下 `s u i l a n` 六个键（再敲一次关闭，状态存本地）。
- 开启后**新建房间**，建房接口才会下发开发者凭证；普通房间永远拿不到开发者权限。
- 开发者可以：一键坐满四个测试席位（测试甲/乙/丙/丁）、一键置四席准备、
  **代替四个席位分别操作**（选格 / 描述 / 作答 / 抢答 / 换题都要走同一套规则校验），
  并且能看到当前格题面方便对照。
- 代打时先在顶栏切到某个席位（红描 / 红猜 / 绿描 / 绿猜），界面只会显示**那个席位**
  该看到的操作 —— 和真人一致，描述位不会冒出抢答按钮。

| 想做的事 | 普通房间 | 开发者房间 |
|---|---|---|
| 坐满四席 | 四个真人各点一席 | 「坐满四个测试选手」一键完成 |
| 准备 | 每人自己点 | 「四席全部准备」一键完成 |
| 代打别的席位 | 不行（服务端覆盖为本人席位） | 可以（按当前行动席位下发操作权限） |
| 看题面 | 只有描述位 | 随时可见 |

## 未明确规定处的默认处理

| 边界情况 | 当前默认 |
|---|---|
| 双方都答错 | **不结算、不换格**，继续交替描述与作答，直到有人猜对 |
| 抢答答错 | 回到原作答方，重新给 90 秒作答（描述保留，不用重写） |
| 防抢答后答错 | 按普通答错处理，转对方描述 |
| 选格超时 | 选格权直接转给对方 |
| 描述超时 | 描述作废，**仍由本方猜词位作答**；作答也超时才转对方描述 |
| 主动跳过 | 与超时同一套处理，记录里标「跳过描述 / 跳过作答」 |
| 描述不合规（不是两字 / 含答案字） | 服务端拒绝并返回原因，界面就地提示修改 |
| 行动方中途离席 | 立刻按超时处理，不让整桌干等 90 秒 |
| 换题次数 | 每格一次，需双方描述位各按一次 |
| 暂停中操作 | 除改昵称 / 复制局面图 / 继续外一律拒绝；倒计时条保持暂停那一刻的长度与秒数 |
| 题库被替换 | 四席准备状态清零，需要重新确认 |
| 房间存活 | 8 小时内无人访问即过期；房主或开发者可随时「解散房间」当场结束，房号立即释放；房号是 3 位数字、从 000 起顺序分配，过期或解散的房间号会被新房间复用 |

这些都集中在 `src/engine.ts`，改一处即可。

## 架构：谁在裁决

```
浏览器（4 台 + N 个观众）       服务端进程                     进程内存
────────────────────          ─────────────                 ──────────────
只做两件事：           ──POST──▶  engine.ts 权威状态机 ──读/写──▶  Map<房号, 行>
  · 每 900ms 拉快照               · 判词、计回合、判胜负         · state  公开快照
  · 提交操作意图                  · 按席位下发题面               · sig    HMAC 防篡改
                                  · 懒判定超时                   · vault  AES-GCM 密文
                                  · 不落任何长期数据              · data/rooms.json 防抖快照（重启可恢复）
```

三条安全线：

| 想作弊的方式 | 被什么挡住 |
|---|---|
| 猜词位打开控制台找答案 | 题面从不下发给非描述位；公开快照里根本没有未揭晓的 `word` |
| 伪造席位去偷看队友题面 | 席位由 `x-seat-token` 反查，客户端自报的 `seat` 一律被覆盖 |
| 冒充房主审批题库 | 审批权限由服务端按 `x-host-token` 判定 |
| 直连存储改棋盘 / 改胜负 | 存储已经搬到进程内存，外部没有入口；`state` 仍带 HMAC 签名，内部错乱也会被拦下（409） |

四枚令牌各管一件事，互不替代：

| 请求头 | 作用 | 能做什么 |
|---|---|---|
| `x-seat-token` | 席位凭证 | 自己席位上的选格 / 描述 / 作答 / 抢答 / 准备 / 离席 |
| `x-host-token` | 房主凭证 | 审批题库（可不在席位上） |
| `x-watch-token` | 观众凭证 | 改昵称 / 传题库；接替空位时用来把自己从观战名单里摘掉 |
| `x-dev-token` | 开发者凭证 | 只在开发者建房时下发；代打四席、看题面、一键布置测试席位 |

`vault`（答案 + 题库提案 + 席位令牌 + 观众名单 + 开发者凭证）用只在服务端进程里的密钥加密。
内存外部读不到，`data/rooms.json` 快照里存的也是密文而非明文答案。密钥可用 `SUILAN_SECRET` 环境变量覆盖。

```bash
npm install

```

```bash
npm run test         # 规则 246 + 判词 16 + 示例题库 9 + 题库包 9 + 明文词表 61 + 身份 17 + 棋盘排版 21 + 历史 6 + 大厅判废 19 + 观战猜词 34 + 判胜换格 11 + 分享码 15
```

## 打包题库

```bash
node tools/pack-bank.mjs --demo --pass demo --out demo.sbank
node tools/pack-bank.mjs --in words.txt --name "华夏风雅" --pass 2468 --out 风雅.sbank
```

`words.txt` 每行一词，可追加 `|提示|分类`；一个词有多种写法时写成 `甲/乙`（任一种都算答对）。
提示与分类字段仍保留兼容，但人机对战已移除，所以它们现在只作为题库元数据。

`--demo` 直接读仓库根目录的 **`词表随射.txt`**（网页里「内置示例题库」用的也是它）：
词表改了要跑 `npm run demo-bank` 重新生成 `src/data/demoText.ts`。

网页里的「明文词库」导入认同一份 `.txt`（`|` 分列照旧），额外还认 Tab 表格粘贴、
以及任意逗号/顿号/空格分隔——不打包成 `.sbank` 也能直接开局。

## 已知取舍

- **同步延迟约 1 秒**。回合制、动作低频，实际无感；但对时限最后 1 秒的操作会有边界抖动。
- **超时靠懒判定**：没有常驻定时器，谁下一次请求谁触发结算。所有人都断线时，计时暂停，恢复后按真实时钟一次性追平。
- **对局状态存在服务端进程内存**，不消耗云服务资源点；代价是重新发布 / 进程重启后房间清空（同一进程内的重启会从 `data/rooms.json` 恢复）。服务端没有账号体系，凭证是设备本地的随机令牌，换设备 / 清缓存需要重新入座（席位空着就能随时坐回去）。
- **没有长期战绩**：结算后的对局不落任何持久存储，进程一重启就查不到。这是换取「零云服务成本」的代价；要恢复得另接存储，并先算清「一次写多大、多久写一次」。
- **自定义词表不保密**：`.sbank` 走服务端解密；**明文词库**的词表会以明文上行，并显示在
  导入者自己那台设备的编辑框里（「实时预览可改」的必要代价）。但两条路线的词表都只进服务端 `vault`，
  其他设备、观众、猜词位都拿不到。界面上的「内置示例题库」（词表随射，2577 词）是公开词库，仅供试玩。
- **对局历史会随对局增长**：一格最多留 30 条描述/作答，整局最多 25 格，快照体积有上限但不算小。
- **观众名单不做超时清理**：一场里关掉页面的观众会留在名单上，因此显示上只保留最近 200 位。
- **开发者凭证只发一次**：只有「开启开发者模式后新建的房间」才有；别人的房间无法事后提权。
